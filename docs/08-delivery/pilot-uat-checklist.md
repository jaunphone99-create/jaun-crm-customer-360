## 2. ความต่างจาก UAT บน staging — **หัวใจของเอกสารนี้**

### 2.1 ทำไมวิธีตรวจต้องเปลี่ยน

`test-cases-uat.md` §4.2 นิยาม UAT ว่าอยู่บน **staging + `seed.sql` + นาฬิกาตรึง** และ §4.4 เกณฑ์ `E-5` เขียนว่า
"ตัวเลขบนหน้าจอตรงข้อ 13 ทุกจุดที่ตรวจ" · §4.3 ถึงกับระบุตัวเลขที่ต้องเห็นบนหน้า 02

**เกณฑ์ข้อนั้นใช้กับรอบ Pilot ไม่ได้** ด้วยเหตุผลสามข้อที่ตรวจสอบได้:

| # | เหตุผล | หลักฐาน |
|---|---|---|
| 1 | ตัวเลขทุกตัวในข้อ 13 ถูกผลิตจาก `supabase/seed.sql` และถูก assert ด้วย `supabase/tests/acceptance.sql` | ข้อ 13.0 กติกา 9 · `test-cases-uat.md` §7 หมายเหตุ U12 |
| 2 | ข้อ 13 ตั้งอยู่บน **"ตอนนี้" = 11 ก.ย. 2569 10:24 น.** ซึ่งมาจาก `app.settings['clock']` ที่ถูกตรึงไว้ | ข้อ 11.2 ระบุว่า **prod ต้อง `clock.as_of = null`** · `roadmap.md` §6.1 `D-2` |
| 3 | ข้อมูลของ Pilot คือข้อมูลลูกค้าเดิมที่นำเข้าตาม `data-migration-plan.md` ซึ่งไม่มีทางให้ยอดตรงกับ seed | `data-migration-plan.md` §7.2 กำหนด `first_seen_at` จากข้อมูลต้นทาง ไม่ใช่จาก seed |

> **ห้ามโหลด `seed.sql` ลง environment ของ Pilot เพื่อให้ตัวเลขตรงเอกสาร** — จะทับข้อมูลลูกค้าจริง
> **ห้ามรัน `supabase/tests/acceptance.sql` หรือ `supabase/tests/jobs_01.sql` บน environment ของ Pilot** —
> `test-cases-uat.md` §4.2 ระบุว่า `jobs_01.sql` ล้างตารางธุรกิจก่อนสร้าง fixture

### 2.2 เกณฑ์ที่ใช้แทน

`E-5` ของ `test-cases-uat.md` §4.4 ถูกแทนด้วย **`E-5P`** สามชั้นต่อไปนี้ในรอบ Pilot **[ข้อเสนอผู้เขียน]**

| ชั้น | คำถามที่ตอบ | วิธีตรวจ | ใครทำ |
|---|---|---|---|
| **E-5P-a** หน้าจอ = RPC | "ตัวเลขที่ผู้ใช้เห็น คือตัวเลขที่ฐานข้อมูลคืนมาจริงหรือไม่" | ทุกตัวเลขบนหน้าจอต้องเป็นสตริง `display` / `change_display` / `pct_display` / `share_display` ที่ RPC จัดรูปแบบมาแล้ว · **หน้าจอห้ามบวกลบหรือคิดร้อยละเอง** (ข้อ 20.14 เกณฑ์ 1 · ขอบเขตที่อนุมัติในข้อ 20.15) | QA — อัตโนมัติด้วย `npm run smoke -- --env <ไฟล์>.json` |
| **E-5P-b** RPC = ตาราง | "ตัวเลขที่ RPC คืน ตรงกับการนับตรงจากตารางด้วยนิยามเดียวกันหรือไม่" | สุ่มตรวจอย่างน้อย 3 ตัวชี้วัด โดยนับตรงจากตารางตามสูตรข้อ 12.1 · 12.2 แล้วเทียบกับค่าที่ `api.get_kpis` คืน — **อ่านอย่างเดียว** | QA + SYSTEM_ADMIN |
| **E-5P-c** ตาราง = ความจริงที่สาขา | "จำนวนที่ระบบบอก ตรงกับสิ่งที่เกิดขึ้นที่หน้าร้านจริงหรือไม่" | เลือก 1 วันของรอบ UAT · ให้สาขานับจำนวนผู้มาติดต่อด้วยวิธีเดิมคู่ขนาน แล้วเทียบกับ `VISITS` ของวันนั้น | BRANCH_MANAGER + ผู้ดำเนินการ UAT |

**กติกาที่ต้องย้ำกับผู้ทดสอบทุกคน**

1. **ห้ามเขียนตัวเลขคาดหวังลงใบงานล่วงหน้า** — ช่อง "ผลที่ควรได้" ของรอบนี้เขียนเป็น *ความสัมพันธ์* ("เท่ากับค่าที่ RPC คืน") ไม่ใช่ *ค่า*
2. **ตัวเลขเปรียบเทียบ (+x% / −x pp) อาจไม่มีความหมายในช่วงต้น Pilot** เพราะช่วงเปรียบเทียบยังไม่มีข้อมูล
   (`roadmap.md` §3.4 หมายเหตุผู้เขียน N3) — **ไม่ถือเป็นข้อบกพร่อง** เว้นแต่หน้าจอแสดงค่าที่ขัดแย้งกับ RPC
3. **"ตอนนี้" ของทุกหน้าจอมาจาก RPC ไม่ใช่นาฬิกาเครื่อง** (ข้อ 20.14 เกณฑ์ 1) — ถ้าเครื่องผู้ทดสอบตั้งเวลาผิด
   ตัวเลขต้องไม่เปลี่ยน · ถ้าเปลี่ยน = **S2**
4. **ป้ายช่วงเวลาต้องเขียน "30 วันล่าสุด" ไม่ใช่ "เดือนนี้"** (ข้อ 12.0 · D27) — ข้อนี้ตรวจได้โดยไม่ต้องรู้ตัวเลข

### 7.4 การตัดสิน go / no-go

| บทบาท | ชื่อ | หน้าที่ในการตัดสิน | ผล | วันที่ | ลงนาม |
|---|---|---|---|---|---|
| ผู้ดำเนินการ UAT | **[รอยืนยัน]** | เสนอผลรวมของรอบ | ☐ Go ☐ Conditional Go ☐ No-Go | | |
| DPO | **[รอยืนยัน Q8]** | **ยับยั้งได้** ถ้ามีประเด็นข้อมูลส่วนบุคคล | ☐ ไม่ขัดข้อง ☐ ขัดข้อง | | |
| `SYSTEM_ADMIN` | **[รอยืนยัน]** | ยืนยันว่า environment · backup · monitoring พร้อม (`deployment-backup-recovery.md` §11.6) | ☐ พร้อม ☐ ไม่พร้อม | | |
| `BRANCH_MANAGER` JP1 | **[รอยืนยัน]** | ยืนยันว่าสาขาพร้อมใช้งานจริง (อุปกรณ์ · คน · การอบรม) | ☐ พร้อม ☐ ไม่พร้อม | | |
| **`EXECUTIVE`** | **[รอยืนยัน]** | **ผู้ตัดสินขั้นสุดท้าย** | ☐ **Go** ☐ **Conditional Go** ☐ **No-Go** | | |

**ถ้าเป็น Conditional Go** ต้องเขียนให้ครบสามอย่าง: ข้อบกพร่องที่ยังเหลือ · ขอบเขตที่เปิดใช้จริงได้ · กำหนดแก้

| ข้อบกพร่องที่เหลือ | ระดับ | ผู้รับผิดชอบ | กำหนดแก้ | ขอบเขตที่ยังเปิดใช้ได้ |
|---|---|---|---|---|
| | | | | |

**ถ้าเป็น No-Go** ให้บันทึกทางถอยที่เลือกตาม `roadmap.md` §6.4 (L1–L5) และวันที่จะทดสอบซ้ำ

### 7.5 หลังลงนาม Go — ยังไม่จบ

ผลของรอบนี้ทำให้เข้าเกณฑ์ **เริ่ม** Pilot ได้ · **เกณฑ์จบ Pilot คือ `P-1` … `P-10` ของ `roadmap.md` §6.3**
ซึ่งวัดจากการใช้งานจริงตลอดช่วง Pilot ไม่ใช่จากใบงานนี้ · ระหว่างนั้นทำ Hypercare ตาม `roadmap.md` §6.5:
ทบทวน `P-3` … `P-8` **ทุกวัน** และสรุปรายสัปดาห์ให้ PO และ `EXECUTIVE`
